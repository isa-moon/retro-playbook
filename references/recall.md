# 开工唤醒

目标：在新项目开工、写方案或排期时，把经验库里**和这个项目相关的**坑、基准和情报翻出来，并写进计划本身。唤醒是用户正事的前奏，要短；不要喧宾夺主。

## 1. 提取项目特征

从用户的请求和材料（brief、需求、邮件）里提取：

- 行业 / 品类
- 平台 / 渠道
- 项目类型（种草、直播、发布会、投放、内容代运营……）
- 合作方（客户、机构、供应商、审核方的名字）
- 约束：时间紧不紧、预算结构、审核链路、KPI 类型
- 这个项目已经暴露出来的风险信号（如「卖点含功效词」「上线窗口只有 10 天」）

## 2. 检索

库很小（INDEX.md 不到 50 条）时，直接通读 INDEX.md，不必再跑 search。

库大的时候多路检索，一路一个角度。`search` 只做字面匹配，对同义词召回很弱（「提亮」搜不到「美白」），所以风险信号要换几种说法各搜一次：

```bash
python3 scripts/lessons.py search <品类+平台> --tags <标签>
python3 scripts/lessons.py search <合作方名字>
python3 scripts/lessons.py search <风险信号原话>
python3 scripts/lessons.py search <项目类型+阶段，如「排期 上线」>
```

另外，用文本搜索在 `复盘/` 里找这个项目的合作方名字。同一客户、同一机构的旧复盘记录里，如果有「待你确认」没了结的风险，或「材料缺口」，也一并提出来，并注明「来自复盘记录，不是教训」。

## 3. 逐条判断是否真的相关

检索靠字面相似，相关与否由你判断。对每条候选：

- 它的 `when` 在这个项目里会不会真的出现？出现在哪一步？
- 它的 `scope` 有没有把这个项目排除在外？scope 写「未验证」不等于排除：可以提，但要标「延伸使用」。
- 只有一部分适用（比如基准数值不适用，附带的动作适用）：只采用适用的部分，并说明为什么。
- `confidence` 是「存疑」或误导次数 ≥ 有用次数的：可以提，但必须带上这个提醒。
- `review_by` 已过期的：提的时候说明「已过复核期，规则可能变了」，并建议顺手体检。

最多选 5 条。宁缺毋滥。

## 4. 呈现

放在交付物最前面，一张表，一条一行，按影响从大到小排：

| 教训 | 这次的信号 | 上次的代价 | 落到计划里的哪一步 |
|---|---|---|---|
| L0007 避坑·单次观察 <标题> | <这个项目里对应的信号> | <一句话> | <排期第几行 / 风险清单第几条> |

细节写进计划本身，不在这里展开。基准类在表里注明「样本 N 个，仅供参照」；存疑、过期、延伸使用、部分采用的，在标题后加括注。

表后问一句：哪些不要。采用的条目已经写进计划并标了「来自经验库 Lxxxx」，用户删掉对应行就行。用户提问仍遵守铁律 1（每轮最多 3 个）；要问客户的问题放进交付物里的客户确认清单，不算在内。

没有相关的就一句话：「经验库里没有和这个项目相关的教训。」然后直接做用户的正事。

## 5. 写进计划，然后记账

- 采用的条目要**写进交付物本身**：方案里的风险项、排期表里的检查点、清单里的勾选项。只在聊天里提一句，等于没唤醒。
- 记账（项目名要写成以后复盘时能搜到的形式，复盘时靠它回填）：

```bash
python3 scripts/lessons.py log L0007 recalled --project 项目名     # 每条被呈现的
python3 scripts/lessons.py log L0007 applied  --project 项目名     # 每条写进计划的
python3 scripts/lessons.py log L0007 applied  --project 项目名 --note "部分采用：只用口径，不用数值"
python3 scripts/lessons.py log L0007 applied  --project 项目名 --undo   # 用户之后删掉了这条
```

## 6. 告诉用户闭环怎么闭上

在唤醒结尾加一句：项目结束复盘时，会回头看这几条到底有没有用。不要多说。
