# 评测

做法参照 Anthropic 的 skill-creator 和 obra 的 writing-skills：先看不装 skill 时 AI 怎么失败，再针对失败写 skill，最后用同一份素材验证。

## 目录

| 路径 | 内容 |
|---|---|
| `fixtures/campaign-chengyan/` | 虚构的护肤品抖音达人种草项目：brief、结案数据、群聊摘录、复盘会纪要。里面埋了几个坑：口头档期被挤占、法务驳回功效宣称、疑似刷量、混杂的「多用腰部」结论、对不上的 CPM 口径 |
| `fixtures/brief-chengyan-sunscreen/` | 同一客户的新 brief，用来测开工唤醒。埋了一个排期冲突：脚本 11/20 定稿，加上约两周的法务审核，晚于 12/1 上线 |
| `baseline/` | 不装 skill 的复盘产出 |
| `runs/with-skill/` | 装 skill 的复盘产出，含它建出来的经验库 |
| `runs/recall/` | 装 skill 的开工唤醒产出。经验库是 with-skill 那份，外加两条无关的干扰项 |
| `rubric-capture.md`、`rubric-recall.md` | 评分表 |
| `trigger_cases.json` | 触发正反例 |

## 结果（2026-10-26，Claude Opus 5.5）

### 复盘：基线 vs 装 skill

| | 无 skill | 装 skill |
|---|---|---|
| 分析质量（重算 KPI、识破混杂、发现刷量） | 很好 | 很好 |
| 沉淀形态 | 一份绑定项目的 checklist，**20 条** | 进跨项目经验库，**5 条**，每条都有 when/do/scope |
| 通用常识和真实教训混在一起 | 是（「48 小时内签约」「投流留 30%～50%」等，数字是模型自己给的） | 否：通用常识不入库，建议值都标了「未验证」 |
| 基准 / 情报 | 无 | 本团队 CPM 基准、澄言法务约两周的审核节奏 |
| 置信度、复核期 | 无 | 全部为「单次观察」或「存疑」，有 review_by |
| 下次能被找到 | 无机制 | 有：search、INDEX、开工唤醒 |
| 评分表 14 项 | — | 14/14（「保持」类没入库，但说明了原因） |

结论：分析能力模型本来就有，skill 带来的增量在沉淀纪律和闭环。这也说明这个 skill 不会随模型变强而失效：模型越强，分析越好，但「存什么、存在哪、下次怎么被想起来」这些问题仍然在。

### 开工唤醒

9/9 通过。用户没提经验库，只靠规则文件里那一行就先查了库。召回了全部 5 条相关教训，没选两条干扰项。用 L0002 算出法务回复约在 12/04，晚于 12/01 上线，于是把送审前移到 11/12、卖点词表在 11/04 单独预审。L0001 的 scope 写着「美白类未验证」，它照样提了，标为延伸使用。全部记了 recalled 和 applied。

### 根据评测改了什么

两轮评测执行者一共提了约 20 条反馈，已修：
- 提问最多两轮；用户的确认集中在入库预览时一次完成。
- 用户确认的归因和材料冲突时：指出一次出处，用户坚持就按用户的写，冲突证据记进正文。
- 「代价大才写成团队特有形态」，补了代价的判断标准和改写示例。
- 定了拆分原则：一条教训对应一个 when。
- 被压下去的风险：要给出可选做法和各自后果；会影响 KPI 结论的，两套数字都给。
- 脚本 `--lib` 放在子命令前后都可以；新增 `trail`（复盘时回填用）和 `log --undo`；search 去掉相关度接近 0 的结果；「存疑」降权从 0.6 改为 0.8。
- 唤醒呈现改成一张表放在交付物最前面，避免喧宾夺主；同时查同一客户旧复盘里没了结的风险。

## 怎么复跑

1. 基线：让一个不装 skill 的 Agent 处理 `fixtures/campaign-chengyan/`，提示词是「帮我复盘一下，把经验沉淀下来，下次做项目能用上」。
2. 装 skill：同样的请求，经验库指到一个空目录，运行命令时加 `HOME=<临时目录>`，以免写入真实环境。
3. 按评分表打分。
4. 注意：`skills/retro-playbook/` 下的 SKILL.md 和 references 里的示例刻意不用澄言案例。修改时别把素材里的答案写进去，否则评测失效。
